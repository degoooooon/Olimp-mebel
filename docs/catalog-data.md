# Договор о данных каталога

Фронтенд не знает, откуда берутся товары. Он ищет в разметке один блок:

```html
<script type="application/json" id="catalog-data">
{ "categories": [...], "products": [...] }
</script>
```

Блок печатает тема WordPress. Если блока нет, работает демо-набор из
`src/js/data.js` — так страницу можно открыть без сервера.

Менять формат надо с обеих сторон сразу: и в теме, и в `data.js`.

## categories

Порядок в массиве — порядок плиток под героем и переключателей в фильтрах.

| Поле | Тип | Обязательное | Что это |
|---|---|---|---|
| `id` | строка | да | Код категории, он же значение поля `cat` у товара. Только латиница, цифры и дефис — это слаг таксономии |
| `label` | строка | да | Подпись для человека: «Диваны» |
| `icon` | строка | да | Имя файла в `src/img/sprite` без расширения. Есть: `sofa`, `armchair`, `table`, `chair`, `bed`, `wardrobe`, `shelf`, `dresser`, `box`, `lamp` |

Категория «Все» в списке не нужна — фронтенд добавляет её сам.

## products

| Поле | Тип | Обязательное | Что это |
|---|---|---|---|
| `id` | число | да | Идентификатор записи. Должен быть постоянным: по нему хранится корзина покупателя |
| `name` | строка | да | Название товара |
| `cat` | строка | да | `id` категории. Если такой категории нет, товар не покажется ни в одном фильтре |
| `price` | число | да | Цена в рублях, целое, без пробелов и знака рубля |
| `old` | число или `null` | да | Старая цена. Если больше текущей — на карточке появится плашка со скидкой |
| `stock` | логическое | да | `false` — карточка покажет «Нет в наличии», кнопка отключится |
| `pop` | число | да | Порядок в сортировке «По популярности», по убыванию |
| `isNew` | логическое | да | Плашка «Новинка» |
| `img` | строка | да | Иконка-заглушка, когда фотографии нет. Имена те же, что у `icon` категорий |
| `photo` | строка | нет | Адрес фотографии. Есть — показывается вместо иконки |
| `srcset` | строка | нет | Набор размеров той же фотографии, как в атрибуте `srcset` |
| `sizes` | строка | нет | Своё значение `sizes`. Без него фронтенд подставит размеры под свою сетку |
| `specs` | массив | нет | Характеристики парами. Показываются в окне товара |

### specs

Массив объектов `{ "name": …, "value": … }`, обе строки. Набор
характеристик у каждого товара свой: у дивана есть спальное место,
у шкафа нет — поэтому это список пар, а не фиксированные поля.

**Ключа нет вовсе, если характеристик нет.** Не пустой массив: фронтенд
проверяет наличие ключа, а по пустому массиву нарисовал бы заголовок
над пустотой. Порядок сохраняется — в нём их ввёл владелец.

```json
"specs": [
  { "name": "Ширина, см", "value": "220" },
  { "name": "Наполнитель", "value": "пружинный блок, войлок, пенополиуретан" }
]
```

В админке это одно текстовое поле, куда вставляют строки вида
`Ширина, см: 220`. Разбирает их `olimp_parse_specs()` в теме — делит
по первому двоеточию, строки без него пропускает.

## Чего фронтенд не делает

**Не проверяет данные по существу.** Если `price` придёт строкой, сортировка
по цене сломается молча. Числа должны быть числами.

**Не чинит битый JSON.** Если блок не разобрался или в нём нет категорий,
фронтенд молча покажет демо-товары. Увидели на сайте «Диван „Гера“» — значит,
тема отдала мусор.

**Не экранирует за тему.** Тексты, которые приходят сюда, фронтенд
экранирует сам перед вставкой в разметку, но JSON внутри `<script>` должна
корректно закрыть сама тема: последовательность `</script>` в названии товара
разорвёт блок. В PHP это делает `wp_json_encode($data, JSON_HEX_TAG)`.

## Пример

```json
{
  "categories": [
    { "id": "sofa", "label": "Диваны", "icon": "sofa" }
  ],
  "products": [
    {
      "id": 42,
      "name": "Диван «Гера»",
      "cat": "sofa",
      "price": 78990,
      "old": 92990,
      "stock": true,
      "pop": 98,
      "isNew": false,
      "img": "sofa",
      "photo": "https://site.ru/wp-content/uploads/2026/08/gera-800x600.webp",
      "srcset": "https://site.ru/wp-content/uploads/2026/08/gera-400x300.webp 400w, https://site.ru/wp-content/uploads/2026/08/gera-800x600.webp 800w"
    }
  ]
}
```
