# Критерии приёмки кода

Парный к [prompt-code.md](prompt-code.md). Тот отвечает на вопрос «как
писать», этот — «можно ли это принять».

Критерии здесь по возможности проверяемые. «Код должен быть чистым» —
не критерий, его нельзя ни выполнить, ни оспорить. «`npm run lint`
завершается нулём, вот вывод» — критерий.

## Главное правило

По каждому пункту ответ ровно один из двух:

- **проверил, вот вывод команды** — с самим выводом, не пересказом
- **не проверял**

Третьего нет. «Должно работать», «скорее всего в порядке», «ошибок
не было» — это «не проверял», записанное другими словами.

---

## 1. Проверяет машина

Запускается, показывает вывод, спорить не с чем.

```bash
npm run lint          # eslint + stylelint + linthtml + editorconfig
npm run build
npm run build:theme
```

Все три завершаются нулём. Не «прошло без красного текста» — именно код
возврата, потому что сборщик умеет молча оставлять неразрешённые пути.

**Вес собранного назван цифрой и сравнён с прошлым разом.** На этом
проекте база такая:

| | сырой | gzip |
|---|---|---|
| JS | 48 КБ | 19,7 КБ |
| CSS | 28 КБ | 5,8 КБ |

Вырос вдвое — объясни чем. Не «добавили функциональность», а какая
именно библиотека или файл столько весит.

**В собранном коде ноль `console.log`.**

```bash
grep -ro 'console\.log' dist/assets/*.js | wc -l   # 0
```

**Заглушек без пометки нет.** `TODO`, `FIXME`, `заглушка`, `временно` —
либо убраны, либо рядом сказано, откуда возьмётся настоящее значение.

**Совместимость проверена по датасету, а не по ощущениям.**

```bash
npm run lint:baseline
```

Планка — Baseline widely available. Но отчёт читается с головой, а не
как список запретов:

- **возможность, от которой зависит раскладка, обязана быть widely.**
  Пропадёт — вёрстка поедет, и это поломка
- **украшение, которое исчезает молча, ниже планки допустимо** — если рядом
  в коде написано, что пропадёт без него. `backdrop-filter` уходит
  в полупрозрачный фон, `accent-color` — в системную галочку, и никто
  не замечает
- **группа в датасете не равна использованию.** `cursor` помечен
  ограниченным из-за сорока экзотических значений; `pointer` есть
  с Safari 11. Такие разбираются поимённо и вносятся в список исключений
  скрипта — с объяснением, а не «чтобы отчёт был зелёным»

Отдельный случай — когда нехватка даёт **видимый дефект**, а не пустоту.
`scrollbar-width: none` в Safari до 18.2 не работал, и рядом с нашей полосой
показывалась системная. Такое либо закрывается вторым правилом, либо
не используется.

**Контрольные числа шаблона сходятся** — это про проекты, где разметка
преобразуется кодом. Для этого:

```bash
grep -c 'home_url' wp-theme/olimp/front-page.php          # 3
grep -c 'olimp-mebel26\.ru' wp-theme/olimp/front-page.php # 0
```

## 2. Проверяется глазами, по списку

Машина это не ловит, поэтому список и нужен.

**Один файл — одна ответственность.** Назови ответственность каждого
нового файла одной фразой без союза «и». Не получилось — файл делится.

**Комментарий стоит там, где решение неочевидно, и объясняет почему,
а не что.** И называет, что сломается без этой строки. Пересказ кода
комментарием не считается и подлежит удалению.

**Пустой `catch` объяснён.** Пустой без объяснения — ошибка, пустой
с объяснением, почему здесь можно ничего не делать, — решение.

**Данные не продублированы.** Каждое значение, встречающееся дважды, —
это отложенное расхождение. Либо один источник, либо явный комментарий
«тот же номер в подвале, правь оба места».

**Всё, что пришло снаружи, экранировано перед вставкой в разметку.**
Из CMS, из хранилища, из адресной строки. Кавычка в названии товара
рвёт атрибут, угловая скобка — всю карточку.

**Данные с той стороны проверены на тип, а не приняты на веру.**
`Number.isInteger`, `Number.isFinite`, белый список известных ключей.

**Магические числа названы.** Число без имени в коде — либо константа
с комментарием, либо переменная в стилях.

**Ключи хранилища версионированы** — `olimp-cart-v1`. Без версии старый
формат сломает корзину у тех, кто заходил раньше.

**Отказ от очевидного решения объяснён.** Не подключил библиотеку,
не сделал страницу, выключил возможность — скажи почему прямо в коде.
Молчаливый отказ читается как забывчивость. **Если возможность выключена,
чтобы не писать код, — это не решение, это дыра.**

## 3. Проверяется в браузере

Не в режиме разработки. В собранной версии — порядок подключения файлов
там другой, и это меняет поведение.

- **Два движка:** Chromium и WebKit. Не один
- **Узкий и широкий экран.** То, что трогают пальцем, — на телефоне
- **С клавиатуры:** Tab проходит по всему, фокус видно, из модального
  окна не выпадает
- **Замедленный процессор.** Отрисовка каталога целиком занимала 110 мс,
  постранично — 5 мс. Разница видна только под замедлением
- **`prefers-reduced-motion`** учтён
- **Без JS страница читается.** Разметку отдаёт сервер, скрипт улучшает

Отчёт автоматической проверки — гипотеза. Дважды тесты сообщали
о поломках доступности, и оба раза ошибались. Воспроизведи руками,
прежде чем чинить.

## 4. Проверяется снаружи

Залогиненный разработчик видит не то, что посетитель: панели админки,
отключённые счётчики, кеш.

- Приватное окно или запрос через `curl`, а не вкладка, где ты в админке
- Отдаёт ли сервер то, что ты думаешь: `curl -sI` и код ответа
- **Сколько адресов в карте сайта, и сходится ли это число с количеством
  сущностей.** Каталог на 41 товар с одним адресом — диагноз, а не успех
- Смешанного содержимого нет: ни одного `http://` на странице по `https`

## 5. Когда «готово» говорить нельзя

- Хоть один пункт помечен «не проверял», и это не оговорено вслух
- Проверено только в режиме разработки
- Проверено только из админки
- Вывод команды пересказан своими словами вместо самого вывода
- Осталось незакрытое, и оно не названо списком

Осталось незакрытое — это нормально. Ненормально назвать это «готово».
Пиши списком: сделано это, осталось это, упирается в такого-то.
